# WikiSearch with Tiger Data and pg_textsearch 1.5.1

Build keyword, semantic, and hybrid search over Simple English Wikipedia in one PostgreSQL database. Course sponsored by Tiger Data.

**Course offer: [$1,000 in Tiger Cloud credit for 30 days](https://tsdb.co/fcc-learn-tsdb).** Follow the linked offer and check the credit and service pricing in your account.

## Version target

This project targets **pg_textsearch 1.5.1**, listed as available on Tiger Cloud in its [October 9, 2026 changelog](https://www.tigerdata.com/docs/get-started/news/new). PostgreSQL 17 is the course target; upstream also supports PostgreSQL 18. Documentation was checked on October 12, 2026. The tagged README, rather than a moving main branch or an older deploy guide, is the SQL reference: [v1.5.1 README](https://github.com/timescale/pg_textsearch/blob/v1.5.1/README.md).

In the Cloud SQL editor, inspect the server before enabling extensions:

```sql
SELECT version();
SELECT name,default_version,installed_version
FROM pg_available_extensions WHERE name IN ('pg_textsearch','vector','vectorscale');
SELECT version,installed FROM pg_available_extension_versions
WHERE name='pg_textsearch' ORDER BY version;
```

On a new service, `00_extensions.sql` enables the default available extension and rejects an installed version below 1.5.1. For exact reproduction, if 1.5.1 appears in the available list and pg_textsearch is not installed, you can run `CREATE EXTENSION pg_textsearch VERSION '1.5.1';` first. A later installed version may work, but rerun the smoke test and check its release notes.

For an older Cloud service, follow Tiger's maintenance/update instructions (pause/resume or the next maintenance event may be required). When 1.5.1 is available, an existing extension can be updated with `ALTER EXTENSION pg_textsearch UPDATE TO '1.5.1';` if a supported update path is present. Do not downgrade a newer installed extension. Reconnect application sessions after an update. Do not manually alter Cloud server configuration.

## Quick start

Use Python 3.11 or 3.12, a few GB of available local disk for Python/model dependencies, and a PostgreSQL service with adequate disk for uncompressed articles plus several teaching indexes. Download time, index builds, and a 25k CPU embedding job depend on hardware; they are not guaranteed to complete within the edited video chapter.

```bash
git clone https://github.com/beaucarnes/wikisearch.git
cd wikisearch
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

On Windows PowerShell use `.venv\Scripts\Activate.ps1` to activate. Edit `.env` and set `DATABASE_URL` to the Tiger Cloud URI, keeping `sslmode=require`. Never publish `.env`. Set `ADMIN_TOKEN` to a random value generated by `python -c 'import secrets; print(secrets.token_urlsafe(32))'` if you want the insert demo.

Run the files in this order. `db.py` reads `.env`, runs trusted local SQL, and prints each result set. The same SQL also works in the Cloud SQL editor or psql.

```bash
python db.py sql/00_extensions.sql
python db.py sql/01_schema.sql
python load.py
python db.py sql/02_baseline.sql
python db.py sql/03_first_bm25.sql
python db.py sql/04_search_fields.sql
python db.py sql/05_phrases_and_transactions.sql
python db.py sql/06_vectors.sql
python embed.py --limit 25000
python db.py sql/07_vector_index.sql
python smoke.py
uvicorn app:app --host 127.0.0.1 --port 8000
```

Open [WikiSearch locally](http://127.0.0.1:8000). In a second activated terminal:

```bash
python query.py 'jazz trumpet new orleans' --mode keyword
python query.py 'animals that make their own light' --mode semantic
python query.py 'Apollo 13' --mode hybrid --explain
python demo_insert.py
```

For an early rehearsal use `python load.py --limit 1000` and `python embed.py --limit 500`. Later run the full loader and embed job. Existing article IDs are left unchanged. A partial rehearsal can include fewer than 25k rows; compare results only after confirming `/health` shows the intended coverage.

After loading the full snapshot, run these sanity checks in the SQL editor. The source-row count should be 241,787. Negative IDs belong to demo inserts, so the count below stays useful after the API demonstration.

```sql
SELECT count(*) AS source_articles FROM articles WHERE id > 0;
SELECT id, title, word_count FROM articles
WHERE id > 0 ORDER BY word_count DESC, id LIMIT 10;
SELECT id, title, word_count FROM articles
WHERE title IN ('Bioluminescence', 'Volcano') ORDER BY title;
```

## Recording the course

The revised production script uses `recording/` SQL files to run one teaching step at a time. They contain the same schema and retrieval concepts as the main SQL files, split for clearer on-screen results. Run them from the project root, for example `python db.py recording/24_bm25_query.sql`. Follow the production script order; the filename minute prefixes identify each section. The original Quick start remains the shortest setup path.

`python record_transaction.py` keeps a single database session open and pauses before rollback so you can show transactional visibility. Press Enter at its two prompts. It rolls the temporary article back, uses a distinct demo term, and does not modify existing articles. The sequence may advance, which is normal even after a rollback.

`recording/progress.sql` is a read-only diagnostic for a second terminal while an index builds. Its empty result does not prove the Python process is stuck: local embedding work and idle connections are outside its active-query filter. For embedding completion, use `recording/41_vector_counts.sql` and wait for `missing_embeddings = 0`.

See `recording/README.txt` for the ordered recording commands. Do not paste the entire list at once. Keep the completed app for the opening preview; no reset of an existing working database is needed.

## Retrieval choices

- **Keyword:** all articles, title + body, English BM25, lower/negative score first. Zero-score results are excluded after candidate retrieval. Application queries always use `to_bm25query(query, 'articles_search_bm25')`.
- **Semantic:** the longest 25,000 positive-ID articles, plus `Bioluminescence` and `Volcano` if outside that group and present in the snapshot. This may be 25,002 rows. Explicit demo-title inclusion is disclosed, not a relevance claim. Query and document vectors use the same model revision. Article text is title + first 1,500 body characters; MiniLM truncates beyond 256 word pieces.
- **Hybrid:** retrieve candidates with direct `ORDER BY` + `LIMIT`, materialize, then assign ranks. Stack weighted rank contributions and sum by ID. Join only final candidates to article text for snippets. Default: 20 candidates per retriever for 10 displayed results, k=60, equal weights 0.5/0.5. This preserves the ordering of unweighted RRF. Larger requested result counts increase candidate depth to at least twice the result limit.
- **Ties:** ID breaks ties within returned candidate lists and final fusion. The exact membership of a tied candidate boundary may vary. That avoids adding a secondary ordering to the inner index retrieval path.
- **Phrases:** use `@@ phraseto_tsquery('english', ...)` with matching `default_text_search_config`. Tokenized phrase matching is not literal substring matching. Phrase checks may recheck the heap. Boolean filtering plus ranking currently filters, scores, and sorts rather than using one optimized combined scan.
- **Safe excerpts:** ts_headline is applied only after top-k selection. Its output becomes text segments; the browser uses `textContent`, never article-derived `innerHTML`.
- **Writes:** `/articles` requires `X-Admin-Token`. It embeds first, then commits the text and vector in one transaction. Negative IDs identify original demo articles. There is no update endpoint: add embedding invalidation/regeneration if you build one.

## Requests

```text
GET /health
GET /search?q=jazz%20trumpet&mode=keyword
GET /search?q=animals%20that%20make%20their%20own%20light&mode=semantic
GET /search?q=Apollo%2013&mode=hybrid&semantic_weight=0.7
POST /articles       X-Admin-Token: <your token>
```

The write body is `{"title":"...","body":"...","url":"https://example.com"}`. Demo writes are disabled while ADMIN_TOKEN is missing or still the example placeholder. This is a localhost teaching app, not a public deployment configuration. Public deployments need an appropriate authentication/rate-limit policy, TLS, connection sizing, monitoring, and a model-serving capacity plan. The connection pool uses four connections per process; every additional worker can load another model copy.

## Alternative embeddings

`text-embedding-3-small` defaults to 1,536 dimensions. To explore it, use a separate `embedding_openai vector(1536)` column and a corresponding index, embed all selected documents with that model, and change **both** query generation and semantic SQL to use the new column/model. Do not mix MiniLM document vectors with OpenAI query vectors, even if you request matching dimensions. The [official embedding guide](https://developers.openai.com/api/docs/guides/embeddings) documents the request and optional dimensions setting. This alternative needs an API key and incurs usage charges; the included application uses only the local model.

## Validation and troubleshooting

The embedding job commits every batch. If it stops, rerun the same `python embed.py --limit 25000` command to process only missing vectors in the original cohort. Connection interruptions now trigger up to five attempts with a fresh connection and increasing waits. Already-saved embeddings are never overwritten, including when the server commits a batch but its reply is lost. Persistent failures still stop with an error. Keep SSL enabled. Wait for `Embedding job complete.` (or an already-embedded message) before building the vector index.

```bash
python -m unittest discover -s tests -v
python smoke.py
```

The unit suite's API tests need `httpx` (`pip install -r requirements-dev.txt`). The integration smoke test needs the completed real database and uses a rollback-only fixture. Read `VALIDATION.txt` for what was actually run when this package was created. No benchmark or result ranking is fabricated.

If the connection fails, check DATABASE_URL and SSL. If `bm25` or `diskann` is unavailable, verify the correct extensions exist in this database and check pg_textsearch preloading for self-hosted installations. If vectors are missing, run `06_vectors.sql`, then `embed.py`, then `07_vector_index.sql`. For CPU memory pressure, lower `--batch-size`. Do not change the model or preprocessing halfway through an existing embedding set; rebuild a new compatible set instead.

The `IF NOT EXISTS` statements make the course setup convenient to rerun, but do not migrate an incompatible pre-existing schema or index definition. Use a dedicated course database. The load script does not overwrite existing rows. Source-model changes and article edits require a deliberate migration.

For a tiny rehearsal table, the planner may legitimately choose a sequential scan. This temporary diagnostic can help inspect the available BM25 path after `03_first_bm25.sql`. It discourages sequential scans only inside this transaction. Use the normal, unforced plan for performance comparisons.

```sql
BEGIN;
SET LOCAL enable_seqscan = off;
EXPLAIN (ANALYZE, BUFFERS)
SELECT title FROM articles
ORDER BY body <@> to_bm25query('volcano eruption', 'articles_body_bm25')
LIMIT 10;
ROLLBACK;
```

`08_operations.sql` reads monitoring information. It leaves force merge and REINDEX commented because they are deliberate maintenance operations. Remove unused teaching/experimental indexes before measuring sustained application writes. Test backup restoration with the needed extension binaries on the destination.

The benchmark figures in the course are vendor-run historical results for pg_textsearch 1.0 versus ParadeDB 0.21.6, on 138,364,158 MS MARCO v2 passages with warm caches. They are not measurements of this application or of 1.5.1. The published latency advantage is 2.4–6.5× for 2–4 lexemes and concurrent throughput is 8.7×, while ParadeDB builds roughly twice as fast. Workload and methodology matter.

Useful next experiments: evaluate both retrievers on equal coverage, chunk articles, add multilingual partial indexes, or rerank candidates with a cross-encoder. Keep a relevance judgment set and measure latency separately from ranking quality.
